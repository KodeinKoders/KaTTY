= KaTTY: specifications
:toc: left
:toclevels: 2
:icons: font
:source-highlighter: highlight.js

[.lead]
What the KaTTY application does, as it is built: its model, its behaviors, its screens, its keys and its limits.

This document describes the application (the `app` and `app-core` modules).
The terminal itself (emulation, keyboard, mouse, selection, images, search) is the library's, and `AGENTS.md` describes it.
The design that the application follows is the "ADE — Terminal Manager" canvas, and the product decisions are in the "ADE — implementation brief".
Where this document and the code disagree, the code is right and this document is to be fixed.


== Scope

KaTTY is a desktop application that organizes terminals for people who run several CLI coding agents at once.

* It shows and arranges terminals, and shows the state that each program in them reports.
* It never reads, writes or interprets what an agent says: it does not read the screen to guess a state, and it installs nothing in the agents.
* A terminal always starts as a plain shell.
The user starts agents, and manages git worktrees, from the shell.
* It runs on macOS on Apple Silicon only, the one platform libghostty-vt is built for.


=== Non-goals

* A launcher, or any way to start a terminal with an agent.
* A settings page, or a configuration per agent.
* Acting on the state of an agent: the board is for looking at.
* Handling rare failures with a design of their own (an agent that crashes, a project folder that is deleted, a shell that does not start).
* Native notifications.
* Keeping the scrollback of a terminal across launches.


== Vocabulary

[cols="1,3"]
|===
| Term | Meaning

| Project
| A folder on the disk, with the workspaces that were opened in it.

| Workspace
| A named group of the terminals of one project, arranged in a tree of splits.

| Terminal
| A shell in a pseudo-terminal, shown in a pane.

| Pane
| What shows a terminal: its header and the terminal.

| Split
| A node of the tree of a workspace, with two sides and a ratio.

| Agent
| A coding agent that runs in a terminal: Claude Code, Codex, Gemini CLI, Antigravity, Copilot CLI.

| Report
| What a program says of itself with the escape sequence OSC 7501.

| State
| What a terminal is doing, as the application shows it: Nothing (idle), Working, Needs input, Done, and a failure.
|===


== Domain model

=== Entities

Every project, workspace, terminal and split has an id that is made when it is created (a UUID) and kept as long as it exists.

[cols="1,3"]
|===
| Entity | Content

| Project
| An id, a name (the folder's name by default), the path of its folder, its workspaces in order, and whether it is open (listed with its workspaces in the sidebar).

| Workspace
| An id, a name, and a tree of panes.

| Split
| An id, a direction (`ROW`: first side on the left; `COLUMN`: first side above), a ratio (the share of the first side), two sides.

| Terminal
| An id, a name (`null` for the automatic name, see <<terminal-title>>), the directory its shell starts in, a color scheme (`null` for the default of the settings).
|===


=== Invariants

* A workspace always has at least one terminal: closing its last terminal removes the workspace.
* A project may have no workspace.
* A split's ratio is between 0.05 and 0.95.
* The same folder is never two projects: adding a folder that is a project selects it.
* The directions of the splits are the ones of the horizontal layout; the vertical layout draws every split turned.


=== Selection

One project, one workspace of it and one terminal of that workspace are selected; the selected terminal has the focus.
A terminal can be maximized; it is then also the selected one.

After any change, the selection is made to point at something: a project, workspace or terminal that is gone is replaced by the first one that exists, and a maximized terminal that is not in the selected workspace is put back.

== Operations

These are the operations of the store, whatever triggers them (a click, a menu, a shortcut, the palette).

[cols="1,3"]
|===
| Operation | Behavior

| Add a project
| From a folder chosen with the system's folder dialog.
The project is named after the folder, gets a workspace named like it (so the first workspace of "api-gateway" is "api-gateway") with one terminal in the folder, and is selected.
The name of that workspace opens for editing, as for any new workspace; a folder that already is a project does not.
A folder that already is a project is selected instead.

| Reorder projects
| By dragging a project (its row in the sidebar, its tile in the rail, its tab in the vertical layout) to another place among the projects; the order is kept.
The selection does not change, and a click that does not move is a click.

| Rename a project
| A blank name is refused; the name is trimmed.

| Remove a project
| After a confirmation.
Its workspaces and terminals are closed; its folder stays on the disk.
The next project is selected, else the previous one.

| New workspace
| A workspace with one terminal in the project's folder, selected, named like the project when it has no workspace, else "workspace", "workspace 2", "workspace 3"… (the lowest number that is free).
Its name opens for editing.

| Reorder workspaces
| By dragging a workspace (in the sidebar, in the panel of the rail or among the tabs) to another place among the workspaces of its project, never to another project; the order is kept.

| Rename a workspace
| A blank name is refused; the name is trimmed.

| Close a workspace
| Its terminals are closed.
The next workspace of the project is selected, else the previous one.
See <<closing>> for when it asks first.

| Split
| The terminal's place becomes a split of the terminal and a new shell, with a ratio of 0.5.
The new shell starts where the split terminal is, and has the focus.

| Close a terminal
| Its sibling takes its space.
The focus goes to the terminal that was before it in the tree, else after it.
The last terminal of a workspace closes the workspace.

| Rename a terminal
| A blank name gives back the default name (the agent's or the shell's).

| Move a terminal to a workspace
| The menu offers the other workspaces of its own project, and no entry when the project has only one.
It is added to the right of everything in the target (a new root split, `ROW`), and has the focus.
A workspace left without terminals is removed.

| Color scheme of a terminal
| A scheme of its own, or the default of the settings.

| Resize a split
| By dragging the gap between panes; the ratio is kept, within 0.05 and 0.95, and a side is never smaller than 160 px.

| Focus a terminal
| Selects its workspace and its project.

| Maximize a terminal
| It floats over the area of its workspace; focusing another terminal, or closing it, puts it back.
|===

The shell of each terminal reports where it is (OSC 7, which shell integration makes zsh and bash send); the terminal's directory follows it.


== Persistence

* The state is kept in `~/Library/Application Support/KaTTY/state.json`.
The system property `katty.support` replaces the folder.
* It is JSON, with a `version` field (1).
It holds the projects, the selection (without the maximized terminal) and the settings.
* It is written 500 ms after the last change, and once more when the application quits.
It is written to `state.json.tmp`, then moved over `state.json`.
* At launch:
** no file is an empty state;
** a file that cannot be read is moved to `state.json.damaged` (then `.damaged.1`…) and the state is empty;
** a file of a later version is moved to `state.json.version-<n>` and the state is empty;
** fields that the application does not know are ignored.
* The application never writes over a file that it could not read.


== Terminals

=== Sessions

* Every terminal of every project has its shell running, whether its workspace is shown or not.
* The shell is the user's login shell (`$SHELL -l`), with `TERM=xterm-256color` and `COLORTERM=truecolor`, and KaTTY's shell integration for zsh and bash.
* A shell starts in the terminal's directory if that folder exists, else in its project's folder if that exists, else in the user's home.
* The terminals that are not on the screen are paused: they produce no frames, keep running, and keep being followed.
While the board is shown, no terminal is on the screen.
* Closing a terminal ends its shell.
Quitting the application ends every shell.
* At launch, every terminal of the saved state gets a new shell; the old programs and the scrollback are not kept.


=== A shell that ends

* What it wrote stays on the screen, followed by `[Process completed]`.
* The header says "Exited", and a strip under the terminal says "Shell exited with code N" with two buttons: Reopen shell (a new shell in the same pane and directory) and Close (closes the terminal).
* Restart terminal (⌘R) does the same as Reopen shell, for a shell that runs.


=== Pane

The header of a pane is 30 px high and holds, from left to right:

. the glyph of its state;
. the tile of its agent, or of a shell;
. its title (see <<terminal-title>>);
. where it is in git, with an icon: the branch, the branch of a linked worktree (with the worktree icon), or the first 7 characters of a detached commit; nothing outside a repository;
. the state in words (Idle, Working, Needs input, Done, Exited), "Needs input" bold and amber;
. a button to maximize it, or to restore it when it is maximized;
. a button that opens the terminal menu.

The git information is read from git's files (not by running git), when the shell changes directory and when a command ends.

The focused pane has a 2 px ring of the accent color; the others have a 1 px border.
A click in a terminal, or anything that gives it the keyboard, focuses it.
The focused terminal takes the keyboard, except while something else has it: a name being edited, a dialog, the color scheme picker, the palette.


[#terminal-title]
=== Title of a terminal

A terminal is called, in this order:

. the name the user gave it;
. the agent that reports in it (OSC 7501): its name, or what the program calls itself when it is not a known agent;
. the agent that runs in it, known by its program (`claude`, `codex`, `gemini`, `agy`, `copilot`): its name;
. the program that runs in it, as the system names it: `emacs` while the user runs emacs;
. the shell (`zsh`): what is left at the prompt, so the title goes back to it when the program quits.

The program is the one that has the terminal in the system (the foreground process of its pty, read every 500 ms), so it needs a shell with job control, which every interactive shell has.
The title is the same in the pane, the dialogs, the board and the palette, and an agent's tile follows it.
A terminal that has a name of its own has "Use process name" after "Rename terminal" in its menu, which removes the name (as does renaming it to nothing).

=== Maximized terminal

* The terminal floats over the area of the workspace, 24 px from its edges, over a scrim of 30 % black.
* The title bar, the sidebar and the header of the workspace stay as they are.
* The terminal's place in the tree is left empty: a session is shown in one place only.
* It grows from its place in the tree to there in 200 ms while the scrim fades in, and shrinks back to its place when it is restored.
The frame of the pane (border, header, corners, shadow) is drawn at its real bounds on every frame.
The terminal is resized once, to its final size, at the start (and once more at the end when it goes back), and what does not fit yet is clipped: the text is never scaled.
* The restore button, or a click outside the terminal, puts it back.
Escape does not: the programs in a terminal use it.


=== Find bar

* ⌘F, or Find… in the context menu, opens a find bar at the top right of the terminal.
* It searches as the user types: ASCII letters without regard for the case, no regular expression.
* It says "N of M", "M results", "No results", or "Searching…".
* Enter and the down arrow button go to the next match, Shift+Enter and the up arrow button to the previous one; Escape and the close button close it and give the keyboard back to the terminal.
* The matches are yellow and the current one orange; closing the bar takes them off.
* There is no match-case option: libghostty's search has none.


[#agent-state]
== Agent state

=== Source

The state of a terminal comes only from the reports of the program in it (OSC 7501, the program status protocol of libghostty-vt).
A report has a state, a kind, a progress, an id (records form a tree with `/`), the program's name (`app`), a title and a message.
The session keeps the records by the rules of the specification: a report replaces its record, a clear removes a record and the ones beneath it, the records that are working or blocked go when a prompt starts or the program exits.


=== Mapping

[cols="1,2,1"]
|===
| OSC 7501 state | KaTTY state, glyph | Board column

| no record, `idle`
| Nothing (Idle): a hollow ring
| Nothing

| `working`
| Working: a ring that spins once a second (still when the system asks for less motion)
| Working

| `blocked`
| Needs input: an amber disc with `!`
| Needs input

| `done`
| Done: a green disc with a check
| Done

| `error`
| Failure: a red disc with `×`, called "Needs input" in words
| Needs input
|===


=== Summary of a terminal

* The state of a terminal is the state of its most urgent record, in this order: needs input, failure, working, done, idle.
* Its program is the `app` of the most urgent record that has one.
* Its note is the message of the most urgent record, else its title; it is shown as plain text.
* "Since" is the time the terminal entered its state; reports of the same state do not move it.
* An agent is *active* while its terminal is Working, Needs input or failed.
* The state of a project is its most urgent terminal's; its counts are the number of terminals in each state, the most urgent first.


=== Seen

A terminal that is Done or failed stays so until the user has seen it: until it is the selected terminal in the Terminals view of a window that has the focus, or "Mark all seen" is used.
Seeing it removes its `done` and `error` records, and the terminal is at rest.

== Layouts

=== Choosing the layout

* Horizontal and Vertical are what they say.
* Auto is Vertical when the window is taller than it is wide, and is decided again when the window is resized.
* The same projects, workspaces and trees are shown in both; only their arrangement changes.


=== Window

* The window is 1440 × 900 by default, and has Jewel's decorated title bar, with the macOS buttons at the left.
* The application's theme (light or dark) does not change the terminals' colors.


=== Title bar

The title bar is 40 px high and holds:

* at the left: the button that folds the sidebar (horizontal layout, Terminals view), and where the user is: `project / workspace`, or "All projects" or the filtered project on the board, or "KaTTY" without a project;
* in the middle: the switch between Terminals and Board;
* at the right: the field that opens the palette ("Search or run a command… ⌘K", or "Commands ⌘K" in the vertical layout), the bell, and the button of the main menu.


=== Horizontal layout

* The project sidebar (272 px), on the left:
** PROJECTS, with a button to add a project;
** a row for each project: a chevron, a folder icon, its name, and its counts;
** under each project that is open: its folder (with `~` for the home), its workspaces (each with a dot for each terminal's state, in the order of the tree), and "New workspace"; any number of projects are open at once, and a new project is open;
** a click on a closed project opens it and selects it, a click on an open project closes it, and the arrow at the left of a project does the same without selecting it;
** a workspace that is added or selected opens its project; closing a project does not change the selection;
** the usage of the agents at its bottom;
** it scrolls when the list is long.
* Folded, it is a rail (56 px): a 36 px tile for each project with two letters (the first letters of its first two words, `api-gateway` is `AG`) and a badge of its most urgent state, a dashed tile to add a project, and the usage as percentages at the bottom.
A click on a tile selects the project, which takes the user to its first workspace only when it was another project (on the project of the selection nothing changes), and opens a panel (264 px) with its folder, its workspaces and "New workspace".
* The workspace, on the right: a 40 px header (its name, "N terminals", Split right, Split down) above the tree of panes, with 8 px between panes.

While an item is dragged it follows the pointer and a 2 px line of the accent color shows between which two it would be dropped; nothing is moved until it is dropped.
The list does not scroll by itself while an item is dragged.


=== Vertical layout

* A bar of project tabs (40 px), each with its name and counts, and a button to add a project at the right; it scrolls horizontally.
* A bar of workspace tabs (40 px), each with the dots of its terminals and its name, the selected one with a 2 px line of the accent color under it; a button for a new workspace; behind a divider at the far right, Split right and Split down.
* The tree of panes, with every split turned.
* The usage, in a bar at the bottom.


=== Without a project

The window shows the welcome: "Add your first project", what a project is, a button "Add project folder…" with ⌘O, and the agents in two sections: DETECTED ON THIS MACHINE, with the number of agents found (each with its program and "Detected"), and NOT FOUND, which lists the supported agents that were not found, with their number, and is folded until the user opens it (it is absent when every agent is found); "Agents you install later appear here automatically."

A project without a workspace shows "This project has no workspace." and a button for a new one.

== Main menu

The main menu, opened from the title bar, is the only place where the application is set up.

* LAYOUT: Auto, Horizontal, Vertical, with "Auto uses Vertical when the window is taller than it is wide."
* THEME: Light, Dark, System.
* TERMINAL COLOR SCHEME: a field with four swatches of the scheme and its name, which opens the color scheme picker.
* FONT FAMILY: a field that opens the list of families ("JetBrains Mono (bundled)" first, then the monospaced families of the system); the font size with − and + by 0.5 px; "Font ligatures" with "Shows sequences like => and != as single glyphs."

A change applies at once to every terminal.
A family that cannot be loaded gives the bundled font.


=== Color scheme picker

* It chooses the default scheme (from the main menu) or the scheme of one terminal (from its menu, with "Default" first, which says the default's name).
* It has a search field (anywhere in the name, without regard for the case), a filter All / Light / Dark with the number of schemes of each, and a list with a swatch, the name and the kind of each scheme.
* It shows the chosen scheme in a real terminal, with the swatches of its palette (background, foreground, red, green, yellow, blue, magenta, cyan).
* A click applies the scheme at once; the picker stays open until its close button or Escape.
* A scheme is dark when the brightness of its background is under half.


=== Monospaced families

The families are the ones of the system whose characters `iIlMW.m1` all have the same width, without the families whose name starts with a dot.
They are listed once, in the background.


== Attention

* The bell of the title bar shows the number of terminals that need the user (Needs input or failed), in amber.
* Its panel (380 px) has:
** NEEDS YOU, with the number and "Mark all seen";
** the terminals that need the user, the most recent first, then FINISHED: the Done terminals that were not seen, the most recent first; each with its glyph, tile, name, how long ago, `project / workspace` and its note;
** "Nothing needs you." when there is none;
** "Jump to next waiting agent ⌘⇧J" at its bottom.
* A click on a row goes to the terminal: the Terminals view, its workspace and project selected, the terminal focused.
* Mark all seen removes what every terminal finished or failed at; the terminals that wait for the user still do.
* Jump to next waiting agent (⌘⇧J) goes to the waiting terminal that follows the focused one in the order of the sidebar, round to the first; nothing when none waits.
* A notice appears at the bottom right of the window for 6 s when a terminal starts needing the user, finishes or fails, unless it is the focused terminal of the Terminals view of a window that has the focus.
It says "<agent> needs input", "<agent> finished" or "<agent> failed", where, and the note; a click goes to the terminal.
* Ages are "now" under a minute, then "N min", "N h", "N d".


== Board

* The Board view has a column for each state, in this order: Nothing, Working, Needs input (with the failures), Done, each with its glyph, title and number of cards.
* Every terminal has a card, shells at rest too.
In a column, the card that has been there for the shortest time is first.
* A card has the state's glyph, the tile, the title (as the pane's), how long ago, `project / workspace`, the branch or worktree, and the note on two lines at most.
Without a note, it says "Idle shell, waiting at the prompt." (a shell), "At rest.", "Working.", "Waiting for you.", "Failed." or "Finished.".
* It is titled "Agent board", with "N agents across M projects".
* It is filtered by project: in the horizontal layout, a sidebar with "All projects" (with the number of agents) and each project with its counts; in the vertical layout, tabs.
* Cards cannot be moved; a click on a card goes to its terminal.
* In the vertical layout the columns are sections, one under the other.


== Usage

=== Installed agents

* The agents' programs are looked for in the `PATH` of the user's login shell, read once with `$SHELL -l -c 'printf %s "$PATH"'` (8 s at most), else in the application's own `PATH`.
* The first folder of the `PATH` that has an executable file of the program's name wins.
* They are looked for again each time the window gets the focus.


=== Sources

The usage is read from the agents' own commands, which do not cost a turn, and never from a credential.
The commands run in `~/Library/Application Support/KaTTY/usage`, not in a project, with nothing on their input.

[cols="1,3"]
|===
| Agent | Source

| Claude Code
| `claude -p /usage --output-format json`, 30 s at most.
The `result` of the JSON is text with a line per allowance: `Current session: 26% used · resets Oct 15 at 5:49am (Europe/Paris)`.
The label is the line's name without "Current ".
A reset without a date is the next time the clock says so; a date that is more than a day past is next year's.

| Antigravity
| `agy --version` first (5 s): versions before 1.1.11 are not asked, since the command costs a turn there.
Then `agy -p /usage --output-format json --print-timeout 20s`, 30 s at most: each bucket of each group of `command.data` is an allowance named after its group, used at `1 - remaining_fraction`, reset at `reset_time`.

| Codex
| `codex app-server`, over JSON-RPC (one object a line): `initialize`, then the `initialized` notification, then `account/rateLimits/read`; 20 s at most, after which the server is ended.
The `primary` and `secondary` windows are allowances: "Session" for about 5 hours, "Week" for about 7 days, else their length.
This was not tried against a real Codex.

| Gemini CLI, Copilot CLI
| None: no command reports it without a turn.
|===

* An agent is read only while it is installed and shown, every 2 minutes, one after the other.
* A command that fails, takes too long, or prints something that is not understood gives no reading; the agent then has no meter.


=== Presentation

* The bar of an agent shows its most used allowance; it is amber from 80 %.
* Full: the tile, the name, "N% used", the bar, "Resets in …" ("53 minutes", "2 hours 10 minutes", "3 days 4 hours", "11 days").
* Compact: the tile, the bar and the percent; the tooltip says every allowance with its reset.
* In the rail: the tile and the percent.
* An agent that is shown without a reading says "No meter" (or "–" in the rail).
* With no agent chosen: "No agents selected."
* The chooser (the "…" of the usage) has "Compact mode", SHOW USAGE FOR with a checkbox for each installed agent, and "Agents are detected from the CLIs installed on this machine."


== Command palette

* ⌘K, or the field of the title bar, opens it over a scrim; ⌘K again, Escape, or a click outside closes it.
* It lists, in this order:
** WORKSPACES: each workspace, with its project;
** TERMINALS: each terminal, with its workspace and state (idle, working, needs input, done);
** COMMANDS: with their shortcuts, the ones that need a workspace or a terminal only when there is one.
* The commands are: Add project folder…, New workspace, Rename workspace, Close workspace, Split right, Split down, Rename terminal, Restart terminal, Find in terminal, Clear scrollback, Maximize (or Restore) terminal, Change the color scheme of the terminal, Close terminal, Jump to next waiting agent, Mark all agents seen, Show the agent board (or Show terminals), Toggle project sidebar, the three layouts and the three themes.
* What is typed is matched with the labels: its letters, in order, without regard for the case and the spaces.
A match whose letters are together, at the start of the text or of a word, in a short label, is better; the matched letters are bold in the accent color.
* The groups stay in their order; in a group, the best match is first; with nothing typed, everything is in its order.
* The up and down arrows move the selection (round the list), Enter does what is selected, a click does what it says; a new query selects the first entry again.
* Going to a workspace or a terminal switches to the Terminals view.


== Keyboard

The window's shortcuts are handled before the terminal sees them.

[cols="1,3"]
|===
| Keys | Action

| ⌘K
| Open or close the command palette.

| ⌘O
| Add a project folder.

| ⌘N
| New workspace in the selected project.

| ⌘⇧W
| Close the selected workspace.

| ⌘D, ⌘⇧D
| Split the focused terminal right, down.

| ⌘W
| Close the focused terminal.

| ⌘R
| Restart the shell of the focused terminal.

| ⌘⇧J
| Jump to the next agent that waits.

| ⌘⌥ + arrow
| Focus the pane next to the focused one, as the screen shows them: among the panes past its edge that share part of its side, the nearest, then the one that shares the most.

| ⌘F, ⌘A, ⌘L
| Find, select all, clear the scrollback: in the terminal that has the keyboard.

| ⌘C, ⌘V
| Copy, paste: the terminal's own.

| F2
| Rename the project or workspace that has the focus in the sidebar or the tabs.
|===

The library's keys (line editing, history, prompt jumps, links) are in `AGENTS.md`.
On other platforms ⌘ would be Ctrl; it would take keys from the shell, and is not done.

=== Hover

Everything that can be clicked in a list (the rows of the sidebar and its "New workspace", the tabs, the tiles of the rail, the cards, the rows of the lists and of the palette) is filled with the hover color while the pointer is over it, except what is already filled because it is selected.

=== Sizes

* Rows 30 px; the headers of panes 30 px; the title bar, the header of a workspace and the tabs 40 px.
* Icon buttons 28 px, 24 px in the headers of panes.
* State glyphs 12 px, 9 px (without their mark) in rows, counts and strips.
* Agent tiles 18 px in headers, 20 px in lists, 24 px in the rail.
* Radii: 5–6 px for buttons and panes, 8 px for menus and cards, 12 px for dialogs.
* The components are Jewel's Int UI where the design has them (buttons, menus, choices, checkboxes, fields, tooltips, splits), and the font of the interface is Jewel's.


== Accessibility

* Every icon button has a description, which is also its tooltip.
* Rows, tabs, cards and items have descriptions that say what they are (a card: "Claude Code in api-gateway / refactor-auth"), and selected ones are marked selected.
* A state glyph is decoration: its state is always said in words next to it or in the description of what holds it.
* The working ring does not spin when the system asks for less motion.


== Limits

* macOS on Apple Silicon only; the Windows title bar is Jewel's but has never run.
* An agent that does not send OSC 7501 shows as a shell.
* Which `app` name each agent sends is not known for sure: names are matched by substring.
* The Codex usage request follows another application's code and was not tried.
* Gemini CLI and Copilot CLI have no usage meter.
* The scrollback and the programs of the terminals are not kept across launches.
* Panes cannot be moved within a workspace, only to another one.
* The agents' tiles are placeholders, and the application has no icon.
