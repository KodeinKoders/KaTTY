= KaTTY
:toc: macro
:toclevels: 2
:idprefix:
:idseparator: -
:source-highlighter: highlight.js
:icons: font

*A terminal emulator for the desktop, written in Kotlin with Compose.*

KaTTY runs your login shell in a terminal that is drawn on a Compose for Desktop `Canvas`.
The terminal emulation is done by https://ghostty.org[libghostty-vt], the library that Ghostty is built on, and the pseudo-terminal is handled by https://github.com/JetBrains/pty4j[pty4j].


== Requirements

* macOS on Apple Silicon.
libghostty-vt is only built for this platform at the moment.
* JDK 25.
It is the LTS that has the final Java FFM API, which the binding to libghostty-vt uses.
Gradle downloads it when it is missing.

NOTE: The application starts `$SHELL -l`, with `TERM=xterm-256color` and `COLORTERM=truecolor`.


== Running

[source,bash]
----
./gradlew :app:run
----

The logs are printed on the standard error stream.
Their level is set in `app/src/main/resources/simplelogger.properties`.

The window stays open when the shell exits, with `[process exited with code N]` below what it wrote.

`./gradlew build` builds everything and runs the tests, which start programs in a pseudo-terminal and draw frames with Skia in memory.
The images that the rendering tests draw are kept in `terminal-compose/build/renders`.


== Modules

[cols="1,3"]
|===
| Module | Role

| `app`
| The application: a window with a `Terminal` that runs the login shell.

| `terminal-compose`
| `Terminal`, the Compose composable that draws a session with the bundled JetBrains Mono, and sends it the keys that are typed.

| `terminal-themes`
| The color schemes of the https://github.com/mbadolato/iTerm2-Color-Schemes[iTerm2-Color-Schemes] collection (811 of them, in `iterm2-color-schemes`), read from the `.itermcolors` property lists with kotlinx.serialization and xmlutil, as themes for a terminal.

| `terminal`
| `TerminalSession`, which runs a program in a pseudo-terminal, feeds its output to a terminal, and publishes what the screen looks like as immutable frames.
It has its own model of keys and frames, so that nothing above it mentions the binding.

| `ghostty-vt`
| The binding to libghostty-vt, in Java FFM.
The Java part is generated by jextract, and a Kotlin API hides it.
|===

The libghostty-vt library and its headers are in `libghostty-vt`, which is not a Gradle module.
Its `README.adoc` says which Ghostty commit it was built from, and how to update it.


== Status

The shell runs, with colors, text attributes, the 811 iTerm2 color schemes (chosen in the field next to the title), wide characters, a cursor, resizing with reflow, and the keyboard, including the Kitty keyboard protocol dead keys, which are shown underlined while they are composed, and the mouse, which is reported to the programs that ask for it (clicks, drags, motion and the wheel, in every protocol), with the pointer shape that they ask for, and the history scrolls (with the wheel, Shift and PageUp, PageDown, Home or End, and a scrollbar that fades out), and text is selected with the mouse (words with a double click, lines with a triple click, blocks with Option and Command; with Shift when a program has the mouse) and copied as soon as the button is up.

What is not done yet:

* pasting;
* the window title, the bell, and the focus events;
* input methods other than dead keys (the candidate windows of Chinese, Japanese and Korean input);
* images, with the Kitty graphics protocol;
* other platforms than macOS on Apple Silicon.
